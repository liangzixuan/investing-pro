# Assess a report comparison in the current check

Status: in development. [Current work](CURRENT_WORK.md) separates source,
client delivery and physical-device acceptance.

## Complete workflow

Open an existing Follow-ups check's company research visit, or explicitly attach
a matching loaded check during a generic company visit. Revisit a private saved
company report and use the existing controls to capture the current report.
The same listing, share class and CIK must match. Keep both complete dated
captures visible, including missing or retained packets and the unverified file
appendix. Imported calculations do not become current financial inputs.

Write the comparison assessment. Choose its check destination explicitly and
preview the whole result: existing authored text, the new assessment and both
report references. Apply changes only that exact current result once. The
existing 2,000-code-point result limit applies to the complete candidate; reject
invalid, duplicate or oversized content without clipping or changing the draft.
The Watchlist comparison-note action remains separate.

Review the exact check in Follow-ups, Complete explicitly, then Save and freshly
Load. Preserve chosen-review position where present, the original company
return target and independently edited Watchlist, Portfolio and valuation work.
Reading, capture, preview and apply do not request a source, complete a check,
save a resource, or restore a report into live models.

## Ownership and unavailable actions

A preview belongs to the current file, report capture, authored comparison and
exact target result. Source, draft, catalog, section, file, company route or
session changes retire it permanently. Restoring identical text cannot revive
an old action. Pending Save, uncertain commands, conflicts and file recovery
pause mutations. Cancel, late file results and reentrant notifications cannot
modify a replacement target. Apply consumes its preview before editing.

The complete destination question and result remain readable. Focus follows
only the explicit action that still owns the current view; loading a resource
does not choose a check or steal focus. Use the selected Precision Desk styles,
wrapping content, visible focus and 44px action targets.

## Verification scope

Focused model and component checks cover complete text and references, exact
identity, Unicode and limits, duplicate rejection, independent saves and stale
action boundaries. A synthetic native journey covers saved report comparison,
the exact Follow-ups destination, explicit completion, Save and fresh Load.
Earlier native journeys remain required. Planned checks do not establish a
pass, live owner-record persistence, browser layout or phone acceptance.
