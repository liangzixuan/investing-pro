# An existing check in company research

Status: in development. [Current work](CURRENT_WORK.md) records source, native
and client delivery acceptance separately.

## Intended workflow

Open a company through Discover, Markets, screening or a settled company link.
The optional personal context section reads current Watchlist, Portfolio and
Follow-ups drafts independently. Explicit Load controls use their existing save
coordinators. An unloaded resource is not an empty collection. Each retained
draft shows its own saved base, unsaved state and recovery status.

Context matches the full listing, share class and current catalog. It never joins
by ticker or issuer alone. The company note remains authored text. A valid
Portfolio projection supplies authored shares, known or unavailable basis and
its confirmation date; these are not a current market value or return.

Choose the matching check explicitly, then use it for this visit. The choice
starts empty even when one check matches. The current resource permits one check
per listing; this feature does not change that schema. A visit opened from
Follow-ups retains its already owned check and chosen-review position.

Attaching a check keeps the original company selection, source origin, CIK,
section, loaded packets and return target. It makes no source request, navigation,
calculation or Save. Write an assessment through the existing editor. An already
loaded filing can be selected for a complete citation preview and explicit apply.
The existing result limit and validation remain; no text is clipped.

Review the exact entry in Follow-ups, Complete or Reopen explicitly, then Save
and freshly Load. Watchlist and Portfolio retain their independent drafts and
saves. Back before this handoff returns to the original company opener. Source
reads remain explicit and keep their original dates and coverage limits.

## Ownership and unavailable actions

An attachment belongs to one current visit and exact check. External check or
draft replacement, identity/catalog changes and session or company navigation
retire it. Reverting values does not renew an old action. An intentional source
section change can retain the association, while captured edit/citation actions
expire and must be acquired from the new current view.

Pending navigation, source transitions, Save, uncertain commands, conflicts and
catalog or file reviews pause edits. Readable retained context stays labelled.
Resource loads retain their normal session-owned coordinator behavior. Their
completion does not select a check, attach it or move focus automatically.

Use explicit source controls to inspect evidence. A retained packet after a
failed refresh is not fresh evidence. A scheduled item does not establish a
publication; a matching identity does not establish relevance to an assessment.
There is no automatic verdict, background monitoring, new source, financial
formula, persistent resource, schema migration or API route.

## Acceptance scope

Invented tests cover generic and settled company routes, full personal context,
exact share-class identity, empty/unloaded/stale resources, explicit attachment,
source-packet and return preservation, assessment/citation, exact-entry Review,
independent Save and fresh Load. Pending and uncertain operations, external edits,
reentrant callbacks, late results and session/route ABA must leave stale actions
unable to mutate newer work. Native evidence retains all prior journeys and a
scoped current frame; it does not establish physical-device acceptance.
