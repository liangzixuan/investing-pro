# Keep a paired company research report

After researching both finalists in the two-company review, prepare one private
HTML report from their retained readings. This source candidate extends the
[two-company workflow](MANAGED_SCREEN_RESEARCH_REVIEW.md); it is not yet a
delivered Android feature.

## Prepare and save

1. In Discover, screen and compare two companies. Open each company, review its
   sources, calculate authored assumptions when needed, and explicitly retain
   its reading. Return to the pair through owned Back.
2. If you change a company's thesis, recapture that company to include the new
   text. The other retained reading stays unchanged.
3. Select **Prepare paired research report**. Both retained readings are
   required. Inspect the complete preview before saving.
4. Select **Download paired research (HTML)** in the browser or **Save paired
   research (HTML)** on Android. Android asks for a destination through the
   system document picker. Cancel leaves the report and drafts intact.
5. Read the saved file with a compatible HTML reader. All source disclosures and
   complete captured JSON are present without scripts, fonts or external assets.

The report includes the original screen criteria/results and each company's full
identity, captured thesis, source states and packets, dated raw closes and
studies, authored valuation inputs/results, sensitivities and refusals. Fiscal
periods, source dates, calculation times and capture times stay independent.
Preparing or saving reads no source, calculates nothing and saves no account
resource. A captured note may contain unsaved edits; the report does not verify
authored claims or establish that any resource was saved.

## Limits and ownership

This is a passive historical reading. It cannot restore inputs, create a dated
check, rank companies or update an account. Existing Watchlist, Follow-ups and
valuation Save actions remain separate.

The complete HTML must fit within 8 MiB. Invalid text or oversized output is
refused before the destination is opened; no part is clipped. Source gaps and
failed-refresh warnings remain in the report. Preparation does not renew data.

Changing or clearing the pair, entering another visit, pending navigation,
resource availability changes, catalog replacement and session retirement
withdraw the prepared report and fence pending delivery. Restoring equal values
does not revive an old handle. A file already written remains at its destination.
A failed write may leave a partial file; inspect that destination before retrying.
Browser **Download requested** confirms handoff only. Android confirms a completed
write to the chosen document; neither message establishes that the file was opened.
