# Compare Annual statements from screening

Choose two loaded results from the [financial screen](MANAGED_FINANCIAL_SCREEN.md)
to read their Annual statements together. The comparison reuses each result's
complete captured report. Selecting a company, changing statement groups and
inspecting sources make no additional Annual request.

## Choose and read

After the screen finishes, or cancellation settles, select **Compare left** and
**Compare right** on two distinct loaded results. A failed or unread result cannot
supply a report. The pair is separate from the shortlist and saved Watchlist.

The comparison shows both exact listing identities. One statement-group control
selects Income statement, Balance sheet or Cash flow for both companies. Each
table keeps its own filing dates and comparative columns. These periods can
differ; the app does not align fiscal years or infer that the companies are peers.

Values and refusals use the existing canonical statement explorer. Exact signs,
decimal amounts, actual flow periods, balance dates and historical-use limits
remain visible. Missing concepts stay unavailable. Inspect each line's original
observation references and each company's independent source context without
another source request. The two contained tables can scroll independently.

## Continue research and return

Open either company's research from its comparison card. The existing screening
source handoff supplies that exact report. Refresh remains explicit. Existing
selected-cell note tools, whole-note Preview, single-use Append, Review, Save,
recovery and per-company captured reports retain their boundaries.

Back returns to the screen's criteria, results, shortlist and selected pair.
Watchlist, Follow-ups and Portfolio drafts remain independently owned. Selecting
a comparison does not add a company, edit a note or save a record.

Clear either choice to compare another result. Criteria edits, cohort changes,
a new run, catalog replacement and session retirement invalidate old comparison
actions. Temporary navigation preserves a valid pair; access loss clears it.
Editing and restoring old text cannot revive a captured action.

The pair lasts for the current session. The accepted on-screen comparison adds
no stored comparison, financial formula, valuation rank, peer classification or
broader issuer coverage. The report increment below is separate from that
delivered surface.

## Capture a private reading report

This workflow is accepted in source and provided in Android 1.56. See
[Current work](CURRENT_WORK.md) for the separate delivery and device limits.

1. Finish the screen, or wait for cancellation to settle, and choose two distinct
   loaded results. A running, foreign or stale result, or one without an admitted
   Annual packet, cannot supply the report. Valid partial-source packets retain
   their failure qualifications and unavailable concepts. Both choices keep their
   exact listing and catalog identities.
2. Choose **Capture comparison report**. Inspect both complete Income statement,
   Balance sheet and Cash flow sets. The capture retains applied screen criteria,
   run outcome and times, original independent source clocks and observation
   references. Fiscal periods can differ. Signs, zero values and unavailable
   concepts stay visible; the report does not align years or infer a peer group.
3. Use **Save comparison report (HTML)** separately. The private reading copy is
   passive, makes no request and contains no saved Watchlist notes or new online
   resource. The whole file must fit its 8 MiB UTF-8 limit. An oversized report is
   refused without clipping. It is not a recipe or importable draft.
4. Open either company's research and return through Back. The selected screen
   pair remains available. Capture a new report explicitly after returning.
   Shortlist transfer, Watchlist Review and each Save remain separate.

Changes to criteria, cohort, run, selected pair, source, catalog, navigation or
session withdraw a capture and cancel unfinished delivery. Restoring old values
does not revive it. Close and Cancel affect the report only. Capture and report
Save do not edit a note, change a shortlist or issue an Annual request.

The preview and file use the same complete passive report view. Native saving
uses the existing chosen-document writer with a report-specific purpose and
header policy. Browser work remains stopped. Automated source and synthetic
native checks establish their recorded scope, not installation or physical-phone
acceptance.

## Keep a dated research check

This workflow is accepted in source and provided in Android 1.57. [Current work](CURRENT_WORK.md) records
source, automated and delivery acceptance separately.

After reading two current loaded results, capture their comparison for a dated
check. Choose **Left company** or **Right company** explicitly. A destination must
already match an exact company in the current editable My Watchlist draft.
An unrelated company or a different share class cannot receive this check.
The shortlist-to-Watchlist review remains a separate action.

Enter a research question and an independent UTC due date. If needed, use the
explicit Follow-ups Load, then preview the current check. Inspect the complete
listing identity, catalog, question and due date beside the captured comparison.
Both complete statement sets retain their original fiscal periods, source clocks,
criteria, references and partial-source qualifications.

The complete saved check contains the question and a concise pair/capture
reference. It must fit the existing 500 Unicode character limit on one line.
Oversized or invalid text stays visible for correction; nothing is clipped.
Full criteria, statements and source packets are excluded from the saved check.
Use the separate HTML report to keep that complete comparison offline.

**Create follow-up draft** creates one entry once. It changes no Watchlist note
and makes no source request or online Save. Review the entry, open company
Research and return through Back, then Save Follow-ups separately. A fresh Load
can retrieve the saved entry through the existing Follow-ups workflow.

Changes to the comparison, source, criteria, run, catalog, destination, question,
date, draft, file review, access, route or session invalidate the pending action.
Restoring earlier values cannot renew it. Capture and preview again explicitly.
