# Keep a dated check from a Markets calendar item

This M3/M4 source candidate connects an already loaded BLS or BEA schedule or
Federal Reserve announcement to the existing Follow-ups resource. Source and
synthetic native acceptance and client delivery remain separate checks.

## Choose, preview and keep the check

1. In **Markets day view**, choose **Keep a dated check** on one loaded item.
   No source request starts. The form shows the original source URL, scheduled
   or publication time, retrieval time and any loaded window. An announcement
   with unknown publication time stays unknown. Retained previous data keeps
   that qualification.
2. Independently choose an exact company from the current editable **My Watchlist**
   draft. No company is selected by default. The source does not establish
   relevance to that company. Inspect the complete listing and share-class
   identity. **Manage My Watchlist** opens its existing load/review workflow if
   a usable draft is missing; this form does not load it automatically.
3. Write a one-line research question and a UTC due date in `YYYY-MM-DD` format.
   The due date is authored and remains separate from every source clock.
4. If Follow-ups has never loaded in this session and is eligible for an initial
   read, choose **Load follow-ups for this question**. Keep the selected company,
   raw question and due date through that read or a recoverable failure. An
   existing authored or unresolved Follow-ups draft cannot be overwritten here.
5. Choose **Preview next check**. Inspect the complete question and citation,
   exact listing and due date. The question and full citation together must fit
   the existing 500 Unicode character limit on one line. Oversized or invalid
   input is refused without clipping. The existing 20-entry limit and one entry per
   listing limit apply; an existing check can be reviewed instead of replaced.
6. Choose **Create follow-up draft** once. This changes only the independent
   Follow-ups draft. **Review follow-up** selects that exact entry in Follow-ups.
   Use its existing company Research and Back actions, then **Save follow-ups**
   separately. A fresh explicit Load can confirm the saved complete entry.

The saved check contains the complete authored question, source name, original
item title, scheduled or publication time (including unknown), and original URL.
The form also shows retrieval time and any loaded window. These readout clocks
are not stored as a new provenance record. Source text does not become a released
economic value, publisher revision, relevance score or automatic reminder.

## Ownership and recovery

A source choice belongs to the exact settled day-view selection, source packets,
source-review state, catalog, Markets visit and active session. Changing these
retires the old choice permanently. Refreshing a source with identical returned
values still requires a new choice. A running source review cannot create a
check. No late source or initial Follow-ups response can renew a closed form.

The preview also belongs to the exact selected Watchlist member, question/date,
Watchlist and Follow-ups coordinator states, and Follow-ups file activity. A
change, Cancel, route transition or session retirement requires a new preview.
Create consumes its preview before notifying the resource model, so duplicate
clicks and notification reentry cannot create another entry. Existing conflict,
uncertain-save, recovery and catalog-review safeguards continue to apply.

The source choice survives its own eligible initial Follow-ups read; it does not
adopt later packets or a replacement company. Research and Back retain the
independent draft through the existing exact-entry route. Saving Follow-ups
never saves the Watchlist note or changes Portfolio or valuation inputs.

## Verification and scope

Invented fixtures cover all three sources, unknown publication time, full Unicode
citations, size and duplicate limits, one-time creation, explicit initial-load
retention, late completion, source refresh, catalog/session/navigation retirement,
file activity, exact-entry Research/Back and separate Save/fresh Load. The native
journey adds the same full flow with distinct share classes and an unsaved
Watchlist note. Its original CI result must pass before client acceptance.

This increment adds no provider, ticker, metric, storage resource, schema,
dependency, API/site deployment or fee. Browser work remains subject to the
owner's current stop. Automated checks do not establish owner-record access,
installation, physical-phone acceptance or sustained daily use.
