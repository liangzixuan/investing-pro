# Cycle 1b-b8 exit matrix

Scope: one ephemeral SCRAM login selects only the existing
`research_cockpit_backup` capability to create an RLS-scoped, synthetic,
data-only custom archive. A separately provisioned database in the same pinned
cluster then receives that archive through a different ephemeral SCRAM login
that selects only `research_cockpit_test_seed`. The archive contains the 21
application data tables and excludes the independently migrated ledger. B8 is
not a full-database, cross-cluster, production-backup, or disaster-recovery
proof. The design is accepted in
[ADR 0020](./adr/0020-authenticated-policy-scoped-data-backup-and-bounded-clean-restore.md).

Source implementation and local verification are complete. All 409 tests across
the 10 database test files, database typechecking, the migration and static
PostgreSQL guardrails, ESLint, Prettier, and the diff check pass. These are
source/local results; no local Docker or live PostgreSQL execution is claimed.
The pinned version 8 live run and independent artifact review remain pending.
Historical B1 through B7 evidence remains valid only for its recorded checks.

## Exit rule

The source/local rows are marked from executable source and focused local
verification; they do not satisfy any live row. Cycle 1b-b8 becomes
live-complete only when the
dedicated PostgreSQL workflow succeeds from a clean checkout against the pinned
image and exact commit, its version 8 record, logs, artifact digest, source
hashes, and independent offline review are retained in a separate evidence
note. ADR acceptance, source presence, local tests, historical B1 through B7
artifacts, or a dump that was not successfully restored cannot satisfy the live
row.

Until that rule is satisfied, B8 permits no new engine claim. Even after a
successful bounded run, the claim must stay narrower than a production backup
or disaster-recovery result: it covers only the 21 RLS-visible synthetic table
payloads restored into an independently provisioned database in the same
ephemeral PostgreSQL 17 cluster. The exact version 8 nonclaims remain
`external_production_incremental_or_continuous_authenticated_backups`,
`full_schema_global_object_cross_cluster_or_cross_version_restore`, and
`disaster_recovery_storage_encryption_retention_rpo_or_rto`, in addition to
every retained version 7 limitation.
