# ADR 0048: bounded personal TypeScript/Python normalization-record agreement

Status: Accepted and **Pass only for exact source revision
`76bd8a1319d6b5feb05da412ca30fe6507c5bdbb`, the direct child of promoted Cycle
2u documentation baseline
`90c20e6eeb6c387015af81f74ba4b8e7aebc444b`.**

## Context

Cycle 2u established the exact complete ten-fact normalization and
manifest-scoped lineage record for the personal local profile. One
implementation can still contain a deterministic defect. The next bounded
step should detect disagreements without claiming that the supplied
parser-result documents came from an independent or correct raw filing parser.

The private comparison is represented only as **owner-approved private
TypeScript/Python validator comparison Pass for one owner-selected corpus**;
private selection and operation material remain outside Git and logs.

## Decision

Add a TypeScript comparator around the repository-pinned Cycle 2u normalizer
and a distinct repository-pinned zero-dependency Python validator. The same
declaration, manifest, normalization-plan, and parser-result byte scope is
supplied to both implementations. The comparator owns the input snapshots,
recomputes the local result, verifies the canonical-LF Python source digest,
launches the pinned Python file with only the same snapshots over standard
input, and owns its canonical standard output before comparison.

The TypeScript path invokes `normalizePersonalFilingFacts`. The Python path
independently validates the inputs and reconstructs the exact complete Cycle
2u record, including exact decimal arithmetic, deterministic identities,
free-cash-flow operands, version windows, lineage, scopes, statuses, and every
other canonical field. It does not call the TypeScript normalizer and does not
receive the TypeScript result.

The comparator accepts agreement only when the canonical bytes of the full
records are identical. It does not compare only hashes, selected fields, or a
semantic projection, and it does not apply numeric tolerance. Root-only input
must reconstruct 10 versions and 0 edges with the corpus-qualified open end;
the optional manifest-linked amendment pair must reconstruct 20 versions and
10 edges. Both paths enforce free cash flow only as exact OCF minus capex and
preserve both operands.

## Failure decision

Any invalid input, TypeScript normalization quarantine, Python source or
execution failure, malformed or noncanonical secondary record, or
canonical-byte mismatch returns one atomic value-free quarantine. It reveals
no private value, fact,
lineage, mapping, identifier, digest, timestamp, side preference, or diff
location. There is no silent repair, fallback acceptance, mismatch tolerance,
or automatic adjudication.

Success returns an immutable deterministic metadata receipt with status
`agreed_for_personal_use`, assurance
`distinct_repository_pinned_implementations_over_one_shared_parser_result_scope`,
and the exact bounded Cycle 2v claim. It binds the input set, normalized record,
agreement, the TypeScript implementation closure, and Python source by SHA-256
without exposing the complete private record. The record, inputs, and private
operation output remain outside Git and logs.

## Independence decision

The claim is limited to distinct repository-pinned TypeScript and Python
validation/reconstruction implementations. The Python validator has no runtime
package dependency and reconstructs the record independently of the local
TypeScript normalizer.

The implementations share the exact declaration, manifest, plan,
parser-result bytes, repository, written contract, operator, host, and likely
failure domain. This decision therefore does not claim independent raw parsing
or extraction; correctness of shared input or specification; accounting truth;
operator, host, key, or failure-domain independence; protection from
common-input/specification error or collusion; or runtime attestation.

## Applicability and nonclaims

This decision applies only to one owner performing local, offline,
noncommercial, nonredistributed research. Enterprise approval, tenant and
multi-user controls, B15/V15, shared-service operation, and production are Out
of scope and reopen if the profile widens.

Cycle 2v also does not establish SEC authenticity or complete provenance;
taxonomy authority or general coverage; amendment discovery or global
currentness; owner-reviewed precision/recall or other quality thresholds;
database/API/web/queue/fetcher composition; or application and production
safety.

## Verification and promotion

Source revision `76bd8a1319d6b5feb05da412ca30fe6507c5bdbb` passed the local release
gate, focused TypeScript/Python tests, privacy checks, both offline verifiers,
and exact-source workflows.
`90c20e6eeb6c387015af81f74ba4b8e7aebc444b` remains the promoted Cycle 2u
documentation baseline. The owner-private comparison is recorded only by its
coarse Pass wording; no selected-corpus or private-run detail is repository
evidence.

## Consequences

Cycle 2v can close exact complete-record agreement between two distinct
repository-pinned normalization validators and atomic value-free conflict
quarantine. It cannot close raw parser/extraction independence because both
paths consume the same parser-result bytes.

Cycle 2w next requires this exact agreement and adds a repository-pinned
secondary worker that receives raw filing bytes and target QNames, but no
primary parser result, normalized record, expected value, or digest. It
compares exact values only at the ten primary-selected dimensionless raw
coordinates per document. This does not establish the shared QName mapping or
primary fact selection, completeness among additional coordinates, excluded
dimensional semantics, primary parser identity or code lineage, general raw-
parser correctness, or quality. Owner-reviewed quality measurement over a
frozen reference set remains the following blocker and is not pre-accepted by
either agreement.
