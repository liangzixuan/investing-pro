# ADR 0040: bounded synthetic source-owned direct-Docker cross-engine lifecycle agreement

Status: Pending source implementation from exact baseline
`1cb7d3ce024cbd29665af7ec4e010da0c380b726`. The source commit, exact-source CI
and dedicated run/job, retained canonical v3 artifact, artifact and evidence
digests, and independent offline-review verdict remain Pending. Promotion
requires one exact single-parent source child, the full local and remote gates,
success-only artifact retention, independent inspection, and independently
anchored offline review. Cycle 2b, real quality, B15/V15, real-data admission,
and production remain Blocked.

## Context

Cycle 2l promotes bounded cross-engine agreement only after each injected child
result binds to the current exact archives and document roles, the host
recomputes pair and execution bindings, and the fixed 20-fact normalization and
reciprocal ten-edge lineage pass. Its v2 evidence does not establish who owns
the injected child factory, runners, or signer, prove fresh container creation
and removal, or bind Docker lifecycle identity into the agreement result.

Cycle 2m closes only that repository-controlled lifecycle gap. Quality
composition remains deferred because synthetic metrics must not consume an
execution result before source ownership, fresh lifecycle behavior, cleanup,
and invocation binding pass. Cycle 2b remains externally Blocked: repository-
owned synthetic manifests, keys, approvals, clocks, signatures, or claimed
human review cannot create its exact external inventory and authority package.

## Decision

Expose one sealed public configuration containing only the exact closed engine
descriptors. Do not accept a public child factory, runner, signer, private key,
lifecycle receipt, child result, or agreement result. The package owns audited
direct-Docker runners and creates an internal ephemeral Ed25519 signer for each
top-level invocation.

Each invocation performs exactly four fresh create/start/attach/remove
container lifecycles. Every accepted, independently recomputable lifecycle
receipt binds archive digest, document role and digest, container-ID digest,
engine id, role, image and implementation digests, key id and SPKI digest, and
`zeroResidue`. The internal audited runner separately validates exact
create/start `--attach`/`rm --force`/residue order plus exit and output
snapshots. No hidden operation transcript is part of the public receipt
preimage. No container may be reused, and cleanup is part of the atomic success
boundary.

Bind the four lifecycle receipts, exact Cycle 2l current-input and reciprocal-
lineage agreement, complete canonical normalization bytes, and ephemeral key
context into one domain-separated invocation binding. Execute the same owned
synthetic inputs twice. Both invocations must normalize byte-identically while
all eight container-ID digests remain unique and all lifecycle hashes and the
two invocation hashes remain distinct.

Any malformed descriptor, signer failure, Docker operation failure, unexpected
operation order or count, child or agreement failure, receipt mismatch,
container reuse, lifecycle/invocation binding collision, removal failure, or
residue returns one atomic empty value-free quarantine. No partial
normalization, container identity, lifecycle receipt, signature, or mismatch detail is
exposed on failure.

The sole target claim is
`bounded_synthetic_source_owned_direct_docker_cross_engine_current_input_and_lineage_agreement_with_lifecycle_binding`.
It remains Pending until the promotion boundary below passes for one exact
single-parent child of baseline
`1cb7d3ce024cbd29665af7ec4e010da0c380b726`.

## Evidence and promotion boundary

The canonical v3 acceptance record must contain exactly six ordered outcomes:
`same-input-direct-docker-distinct-lifecycle-invocations` agrees across two
invocations over the same exact owned synthetic input pair, while
`unknown-python-image`, `pre-aborted-signal`, `original-archive-tamper`,
`original-amendment-role-swap`, and `identical-archives` each return one atomic
empty value-free quarantine. Each successful invocation performs four fresh
lifecycles. The complete normalization bytes match across invocations, all eight
container-ID digests and lifecycle bindings are unique, and the two invocation
bindings are distinct.

The frozen baseline is `1cb7d3ce024cbd29665af7ec4e010da0c380b726`.
Promotion requires exactly one single-parent source child with parent line
`<source> 1cb7d3ce024cbd29665af7ec4e010da0c380b726`; full local verification;
required exact-source Ubuntu/Windows and dedicated lifecycle workflows; a
success-only retained canonical v3 artifact binding the source transition,
outcomes, ordered checks, ordered nonclaims, images, source hashes, and workflow
identity; artifact and evidence digest inspection; and independent offline
review against separately supplied repository, revision, run, attempt,
artifact, and evidence-digest anchors.

The source SHA, transition inventory, local counts, passing run/job numbers,
artifact identity and size, digests, source-hash count, and offline verdict are
Pending. They may be recorded only after the live artifact exists and the
independent review passes. Cycle 2l v2 and Cycle 2k v1 artifacts, anchors, and
source history remain immutable. Failed-run records remain immutable
non-evidence. Cycle 2m v3 is additive and cannot rewrite or relabel them.

## Consequences

A future Pass would establish only the bounded source-owned synthetic direct-
Docker lifecycle, cleanup, repeat freshness, and invocation-binding claim. It
would not authenticate the Docker daemon, host, kernel, or container IDs;
attest the worker-image supply chain; semantically prove the absence of worker-
internal nonce or cache behavior; establish an external signer identity or
KMS/HSM custody; prove real parser quality; establish Cycle 2b authority; cover
100 real filings or 2,000 independently adjudicated assertions; compose
B15/V15; admit real data; or authorize production.
