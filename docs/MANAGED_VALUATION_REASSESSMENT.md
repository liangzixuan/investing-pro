# Saved valuation reassessment

Compare a confirmed saved valuation entry with revised authored inputs in the
existing company workbench. The baseline is a passive copy. The workbench remains
the only editor, and each resource keeps its own Save action.

## Workflow

1. Open the exact company and share class. Load Saved valuation inputs explicitly.
2. Choose **Use as reassessment baseline** beside a matching confirmed entry.
   The baseline shows its full identity, catalog digest, saved resource version,
   capture time, model versions and every raw input. Capture does not restore the
   entry, change the editor, read a source, calculate or save.
3. Review and edit the workbench inputs. Existing Price and Annual reads remain
   explicit. Review and apply an Annual revenue basis separately when useful.
4. Choose **Calculate** once. **Saved inputs evaluated now** and **Revised authored
   inputs** use the same evaluation time. Both sides show complete DCF and Exit
   results, assumptions, projections, sensitivity tables and model refusals.
5. Use the current revised calculation to prepare a note or dated check. Author
   the reason for the reassessment explicitly. Review and Stage valuation inputs
   before their Save; Watchlist and Follow-ups Save actions remain separate.

The baseline must come from the latest loaded confirmed valuation resource, not
a draft or a file-reported appendix. After Save, Load again to check the latest
shared version before selecting a new baseline. Different share classes are not
interchangeable, including share classes of the same issuer.

## Times and source evidence

The saved resource contains authored inputs, not a historical calculated result.
The baseline capture time and the paired evaluation time describe those actions.
They do not establish a source date. This increment does not retain Price or
Annual packets in the paired reading. The existing source panels show their own
evidence, original times and qualifications. Source completion does not silently
replace either calculation. The app supplies no inferred reason, verdict or
trade instruction.

## Retention and invalidation

Explicit Back to the workspace retains the passive baseline and paired reading
in memory. Return to the same exact company to resume without another calculation
or source read. Button Back and an owned history Back use this path. Normal visit
closure, a different company or share class, catalog replacement, editor discard
or restore, valuation resource Load or Save, file activity and session retirement
retire the baseline. Returning cannot revive a retired capture.

An authored input change retires the paired reading but keeps the baseline.
Calculate again to compare the new inputs. Invalid raw text stays visible and
produces the existing model refusal; rejected over-limit input blocks calculation.
Cancel reassessment clears only the baseline and its paired reading. It preserves
editor inputs, source states and all resource drafts.

Only the current revised calculation can authorize note and dated-check actions.
The saved-side result is passive. Stale renders and reentrant replacement actions
cannot calculate, capture or move focus using an earlier context.
